# Testing

## 현재 기준

- 현재 저장소에는 테스트 파일이 없다.
- 새 테스트 규칙은 지금 코드베이스에 바로 적용 가능한 수준으로만 정의한다.

## 우선순위

- 순수 함수가 분리된 경우 먼저 단위 테스트를 추가한다.
- reducer, custom hook, 데이터 변환 함수가 다음 우선순위다.
- 시각 표현만 있는 단순 UI는 테스트 우선순위를 낮춘다.

## 테스트 대상

- 필터링, 정렬, 비교, 파생 상태 계산 함수
- reducer의 상태 전이
- query option 조합 로직
- 인증/라우팅처럼 분기 조건이 많은 유틸 함수

## 네이밍

- 테스트 파일명은 대상 파일명 기준 `*.test.ts` 또는 `*.test.tsx`를 사용한다.
- describe 제목은 대상 모듈명, test 제목은 기대 동작을 한국어 또는 명확한 영어로 작성한다.

## 원칙

- mock은 필요한 범위만 최소화한다.
- 외부 API 통신은 실제 네트워크 대신 mock 또는 MSW 기반으로 다룬다.
- 구현 세부사항보다 입력과 출력, 사용자 관찰 가능 동작을 검증한다.
