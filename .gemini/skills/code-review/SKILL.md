# Code Review

현재 브랜치의 PR에서 `gemini-code-assist` 리뷰 코멘트를 가져와 반영하는 워크플로우를 수행한다.

## 실행 순서

### 1. PR 및 리뷰어 확인

```bash
gh pr view --json number,url,reviewRequests,reviews,comments
```

- `reviewRequests` 또는 `reviews` 에서 리뷰어 목록을 확인한다.
- `gemini-code-assist` 가 리뷰어에 포함된 경우 다음 단계로 진행한다.
- 포함되지 않은 경우: "@gemini-code-assist 리뷰어가 없습니다. 리뷰어를 추가하거나 수동으로 리뷰를 요청하세요." 를 출력하고 종료한다.

### 2. 리뷰 코멘트 수집

```bash
gh api repos/{owner}/{repo}/pulls/{pr_number}/reviews
gh api repos/{owner}/{repo}/pulls/{pr_number}/comments
```

- `gemini-code-assist` 가 작성한 코멘트만 필터링한다.
- 코멘트를 파일 경로, 라인 번호, 지적 내용 단위로 정리한다.
- 리뷰 상태가 `APPROVED` 이면 "이미 승인된 리뷰입니다." 를 출력하고 종료한다.

### 3. 지적 사항 분류

각 코멘트를 아래 기준으로 분류한다:

| 분류         | 기준                                                                | 처리 방법                 |
| ------------ | ------------------------------------------------------------------- | ------------------------- |
| 자동 수정    | 포맷, 네이밍, 불필요한 import, 타입 단언 등 명확한 코드 스타일 위반 | 즉시 코드 수정            |
| 검토 후 수정 | 로직 변경, 구조 개선 등 의도 파악이 필요한 항목                     | 변경 사항 설명 후 수정    |
| 스킵         | `nit:` 접두사가 붙은 코멘트 또는 칭찬 성격의 코멘트                 | 수정하지 않고 목록에 기록 |

### 4. 코드 수정 적용

- 각 지적 사항을 파일/라인 단위로 수정한다.
- AGENTS.md의 코드 컨벤션(`코드 스타일`, `아키텍처`, `컴포넌트 컨벤션` 등)을 따른다.
- 수정 후 `npm run type-check` 를 실행해 타입 오류가 없는지 확인한다.

### 5. 반영 요약 코멘트 작성

모든 수정이 완료되면 PR에 다음 형식으로 코멘트를 남긴다:

```bash
gh pr comment {pr_number} --body "..."
```

**코멘트 형식:**

```
## Gemini 코드 리뷰 반영 요약

### ✅ 수정 완료
- `파일경로:라인` — 지적 내용 요약 및 처리 방법

### ⏭️ 스킵
- `파일경로:라인` — 스킵 이유 (nit / 칭찬 등)

### ❓ 미결 사항 (있는 경우)
- `파일경로:라인` — 판단이 필요한 항목 및 질문
```

## 주의 사항

- 컨벤션과 충돌하는 Gemini 제안은 수정하지 않고 미결 사항으로 기록한다.
- 여러 코멘트가 동일 파일에 있을 경우, 수정 순서가 라인 번호 충돌을 일으키지 않도록 아래쪽 라인부터 역순으로 수정한다.
- 수정 도중 타입 오류가 발생하면 즉시 중단하고 원인을 사용자에게 알린다.
